## Freshness Scoring (2026-07-06)

An incremental `Freshness_Score` was added to `Momentum_Detector_V6.py` to explicitly reward recent/fresh breakout behaviour and mildly penalize long-stretched momentum runs. Implementation notes:

- Field: `Freshness_Score` is now present in the CSV output and in the engine `scores` dictionary.
- Range: the component is bounded to `[-10, +15]` and is added into `scores["raw"]` before the existing `min(100, ...)` cap.
- Purpose: reward proximity to the 20-day high (strongest for <2% from 20D high) and reduce praise for very-old large extensions.
- Behaviour: it contributes to the overall `Score`, but the engine still caps `raw` and `final` scores at `100`.
- Behaviour: it contributes to the overall `Score`, and because it is summed into `scores["raw"]`, it therefore affects the final reported `Score` (still capped to 0..100 by the existing clamps).
- Validation: a targeted backtest run for the current 23 active tickers confirmed no score exceeded `100` and the decision thresholds for `Momentum Candidate` / `Watchlist Candidate` remain the same.

Files affected:

- `Momentum_Detector_V6.py` (scoring addition and CSV output field)
- `docs/V6_CURRENT_OUTPUT_CONTRACT_2026-07-05.md` (contract note updated)
- `V6_Backtest_Signal_Audit.csv` and `V6_Backtest_Summary.csv` (backtest artifacts)

If you prefer the `Freshness_Score` to be advisory only (not contributing to the raw score), I can change it to be an independent field used for labeling rather than summation into `scores["raw"]`.
